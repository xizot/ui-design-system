# Polish Command

Use when the UI already exists but feels rough, inconsistent, generic, or too busy.

## Polish Targets

System:

- Replace custom primitives with Xizot components.
- Remove local variants that duplicate design-system variants.
- Keep tokens semantic and component APIs intact.

Layout:

- Tighten spacing and alignment.
- Reduce decorative wrappers and nested cards.
- Improve toolbar grouping, grid rhythm, and responsive wrapping.

Typography:

- Improve hierarchy without hero-scale app text.
- Normalize labels, metadata, table density, and action labels.
- Keep muted text secondary.

Color:

- Use color for semantic status, selection, destructive risk, and useful emphasis.
- Reduce ornamental color and one-off palette classes.
- Check light/dark contrast.

UX:

- Improve button hierarchy and action grouping.
- Clarify headings, labels, placeholders, empty states, and destructive actions.
- Preserve loading, disabled, selected, and error states.

## Bounded Pass

Inspect once, edit in one focused batch, then verify. Avoid endless micro-polishing. Preserve product behavior and data flow unless a bug blocks the UI quality.

## What Good Looks Like

The screen should feel like a mature internal product: fast to scan, visually calm, obvious next actions, strong system consistency, no ornamental noise, and no local styling that will become a maintenance burden.
